# Authority Dataset Discovery Endpoints

## Purpose

This adds a dataset-level `authority` flag so WHG can mark which datasets should be used as authority sources in the new Elasticsearch indices.

A machine client can now:
1. Discover all authority datasets (with IDs and place counts), then
2. Fetch each dataset's LPF dump via the Entity API.

## Admin-only update point

- Flag field: `Dataset.authority` (boolean, default `false`)
- Intended edit UI: Django admin dataset change page, e.g.
  - `/admin/datasets/dataset/<id>/change/`

The field is exposed in Django admin (`datasets/admin.py`) and not added to public dataset forms.

## Discovery endpoint (Reconciliation API)

### GET `/reconcile/authority-datasets`

Returns basic details for all datasets with `authority=true`.

- Auth: token/session auth (same as other authenticated reconcile endpoints)
- Query params:
  - `token` (API token; can also use `Authorization: Bearer <token>`)

#### Example request

```bash
curl -s "https://whgazetteer.org/reconcile/authority-datasets?token=<API_TOKEN>"
```

#### Example response

```json
{
  "result": [
    {
      "id": 1760,
      "title": "Example Authority Dataset",
      "place_count": 48231
    }
  ]
}
```

## Fetching dataset LPF from Entity API

For each `id` returned above, fetch LPF via:

### GET `/entity/dataset:<id>/api?filetype=lpf`

#### Example request

```bash
curl -L -o "dataset_1760.lpf.gz" \
  "https://whgazetteer.org/entity/dataset:1760/api?filetype=lpf&token=<API_TOKEN>"
```

Notes:
- Endpoint returns a streaming response with `Content-Encoding: gzip`.
- The payload corresponds to that dataset entity export generated by the Entity API.

## Why this is under Reconciliation API

Dataset discovery by authority status is a source-selection/discovery concern for reconciliation/index pipelines, so it is implemented as a reconciliation helper endpoint.

The Entity API remains the right place for retrieving the actual dataset LPF content once IDs are known.
